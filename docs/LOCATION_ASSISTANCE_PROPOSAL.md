# ข้อเสนอแนวทางการแก้ไขปัญหา: การระบุตำแหน่งผู้ประสบภัยทางโทรศัพท์
> **เอกสารข้อเสนอทางเทคนิคและสถาปัตยกรรม (Technical Proposal & Architecture Guide)**  
> โครงการ: ระบบบริหารจัดการและประสานงานช่วยเหลือผู้ประสบอุทกภัย กองทัพอากาศ (RTAF Flood Relief Operations System)

---

## 📌 1. ปัญหาและข้อจำกัดในปัจจุบัน (Problem Statement)
เมื่อเจ้าหน้าที่ประจำศูนย์รับโทรศัพท์จากผู้ประสบภัย มักพบปัญหาสำคัญดังนี้:
1. **ผู้ประสบภัยตื่นตระหนกและบอกทางด้วยภาษาพูด / คำย่อเฉพาะถิ่น (Local Slang/Landmarks):**  
   เช่น *"ติดอยู่บ้านชั้น 2 ซอย 17 บ้านทุ่งรี แถวๆ มอ."* (มอ. = มหาวิทยาลัยสงขลานครินทร์)
2. **เจ้าหน้าที่รับสายไม่ใช่คนในพื้นที่:** ทำให้ไม่รู้จักชื่อซอยย่อยหรือจุดสังเกตเฉพาะถิ่น
3. **ระบบค้นหาแผนที่ทั่วไป (เช่น OpenStreetMap Nominatim) มีข้อจำกัด:** ไม่สามารถประมวลผลคำย่อหรือคำพูดภาษาไทยได้แม่นยำ เจ้าหน้าที่ต้องเสียเวลาลากแผนที่เพื่อหาตำแหน่งเอง ส่งผลให้การช่วยเหลือล่าช้า

---

## 🗺️ แนวทางที่ 1: ระบบ "Smart Address Search" (ค้นหาสถานที่อัจฉริยะบนแผนที่)

### 🎯 เป้าหมาย
ให้เจ้าหน้าที่สามารถพิมพ์คำย่อ ชื่อซอย หรือแลนด์มาร์กภาษาพูดลงในช่องค้นหาบนแผนที่ แล้วแผนที่จะซูมและปักหมุดตรงจุดเกิดเหตุให้อัตโนมัติภายใน 5–10 วินาที

### 🔄 ขั้นตอนการทำงานจริง (User Flow)
```
[ผู้ประสบภัยโทรแจ้ง: "ซอย 17 ทุ่งรี แถว มอ."]
               │
               ▼
[เจ้าหน้าที่พิมพ์ "ทุ่งรี 17" ในช่องค้นหาบนแผนที่]
               │
               ▼
[ระบบแสดง Auto-Suggest: "ซอย 17 บ้านทุ่งรี, คอหงส์, หาดใหญ่"]
               │
               ▼
[เจ้าหน้าที่คลิกเลือก -> แผนที่ Pan & Zoom ไปปากซอย 17 ทันที]
               │
               ▼
[เจ้าหน้าที่ถามเสริม: "เข้าซอยลึกไหม รั้วสีอะไร" -> ปรับหมุดตามแนวถนน -> บันทึกสำเร็จ]
```

### ⚙️ สถาปัตยกรรมและกลไกการทำงาน (Technical Architecture)
1. **Forward Geocoding with Bounding Box Restriction:**
   - เชื่อมต่อ Search API ที่แม่นยำในประเทศไทย เช่น **Longdo Map API** หรือ **Google Places API**
   - กำหนดขอบเขตการค้นหา (Viewport Bounding Box) เฉพาะพื้นที่ปฏิบัติการ เช่น **อ.หาดใหญ่ / จ.สงขลา** (Lat: 6.8–7.2, Lng: 100.3–100.7) เพื่อป้องกันไม่ให้คำค้นหลุดไปต่างจังหวัด
2. **Local Landmark & Alias Mapping (พจนานุกรมคำย่อท้องถิ่น):**
   - มีระบบจดจำคำย่อ เช่น `"มอ." / "ม.อ."` &rarr; มหาวิทยาลัยสงขลานครินทร์, `"ตลาดกิมหยง"`, `"ไดอาน่า"`, `"ช่องเขา"`
3. **แผนที่ภาพถ่ายดาวเทียม (Satellite Layer):**
   - เพิ่มเลเยอร์ภาพดาวเทียมเพื่อให้เจ้าหน้าที่เปิดดูหลังคาบ้าน ทรงอาคาร หรือลักษณะซอย เพื่อยืนยันกับผู้ประสบภัยได้ทันที

### 💡 จุดเด่นและข้อจำกัด
- **จุดเด่น:**
  - เจ้าหน้าที่ไม่ต้องเปิดแท็บอื่นเพื่อหาทาง ทำจบในหน้าจอลงข้อมูลเดียว
  - รองรับโทรศัพท์ทุกประเภท (แม้ผู้ประสบภัยจะใช้โทรศัพท์ปุ่มกดธรรมดาที่ไม่มีอินเทอร์เน็ต)
- **ข้อจำกัด:**
  - ยังต้องพึ่งพาการสื่อสารทางคำพูด หากผู้ประสบภัยไม่รู้ว่าตนเองอยู่ที่ไหนเลย จะหาตำแหน่งได้ยาก

## 📲 แนวทางที่ 3: ระบบ "SMS One-Click Location Request" (ขอพิกัด GPS อัตโนมัติ)

### 🎯 เป้าหมาย
แก้ปัญหาในกรณีที่ผู้ประสบภัย **"ไม่รู้ตำแหน่งที่อยู่ของตนเอง"** (เช่น มืดสนิท, น้ำท่วมมิดป้ายซอย, หรือเป็นคนต่างถิ่น) โดยส่งลิงก์ผ่าน SMS ให้ผู้ประสบภัยกดส่งพิกัดดาวเทียม (GPS) ความแม่นยำสูง (5–15 เมตร) กลับมาขึ้นบนหน้าจอเจ้าหน้าที่โดยตรง

### 🔄 ขั้นตอนการทำงานจริง (User Flow)
```
[ผู้ประสบภัย: "มืดมากครับ ไม่รู้เลยว่าอยู่ซอยไหน น้ำท่วมหมดแล้ว"]
               │
               ▼
[เจ้าหน้าที่กดปุ่ม "📲 ส่ง SMS ขอพิกัดดาวเทียม" จากหน้าจอ Dashboard]
               │
               ▼
[ผู้ประสบภัยได้รับ SMS: "ศบภ.ทอ. กรุณากดลิงก์เพื่อส่งพิกัดช่วยชีวิต [link]"]
               │
               ▼
[ผู้ประสบภัยแตะลิงก์ -> เปิดหน้าเว็บมือถือ -> กดปุ่ม "📍 ส่งพิกัดของฉัน"]
               │
               ▼
[มือถืออ่านค่าชิป GPS ดาวเทียม -> ส่งพิกัด Lat/Lng กลับมาที่ Server]
               │
               ▼
[หน้าจอของเจ้าหน้าที่ที่กำลังคุยสายอยู่: แผนที่กระโดดไปปักหมุด ณ จุดเกิดเหตุจริงแบบ Real-time]
```

### ⚙️ สถาปัตยกรรมและกลไกการส่ง SMS
1. **ช่องทางการส่ง SMS:**
   - **ตัวเลือก A (SMS Gateway Provider ในไทย เช่น ThaiBulkSMS / SMSMKT):**  
     ระบบยิง API ไปยัง Gateway ส่งข้อความถึงมือถือผู้รับภายใน 2–5 วินาที พร้อมตั้งชื่อผู้ส่งทางการได้ เช่น `RTAF-AID`
   - **ตัวเลือก B (Government / Defense Gateway):**  
     เชื่อมต่อกับเครือข่าย SMS กลางของกองทัพอากาศ หรือความร่วมมือร่วมกับ **NT (โทรคมนาคมแห่งชาติ)**
   - **ตัวเลือก C (GSM Modem Hardware ประจำศูนย์):**  
     ใช้แอร์การ์ดใส่ซิมการ์ด 4G เสียบกับเครื่อง Server ประจำศูนย์เพื่อสั่งยิงข้อความ
2. **เทคโนโลยีหน้าเว็บรับพิกัด (Mobile Web Client):**
   - ผู้ประสบภัยไม่ต้องโหลดแอปพลิเคชันใดๆ ทั้งสิ้น ทำงานผ่านเบราว์เซอร์มาตรฐาน (Safari / Chrome)
   - ใช้ **HTML5 Geolocation API (`navigator.geolocation.getCurrentPosition`)** แบบ `enableHighAccuracy: true` เพื่อดึงพิกัดตรงจากชิปดาวเทียม GPS
   - ส่งผลลัพธ์กลับสู่หน้าจอเจ้าหน้าที่แบบ Real-time ผ่าน WebSocket หรือ Polling

| :--- | :--- | :--- |
| **ความสะดวกของผู้ประสบภัย** | สบายที่สุด (แค่คุยโทรศัพท์ตามปกติ) | ต้องกดเปิดลิงก์ SMS แล้วกดปุ่ม 1 ครั้งบนมือถือ |

## 🎯 ข้อเสนอแนะเชิงกลยุทธ์ (Strategic Recommendation)
เพื่อให้ระบบรองรับสถานการณ์ภัยพิบัติได้ครอบคลุม 100% ในทุกมิติ ขอเสนอให้ **นำทั้งสองแนวทางมาเสริมการทำงานร่วมกัน**:
- **ใช้แนวทางที่ 1 เป็น "เครื่องมือหลัก (Primary Tool)":** สำหรับทุกเคสที่โทรเข้ามา เจ้าหน้าที่สามารถพิมพ์ชื่อซอยและแลนด์มาร์กหาดใหญ่เพื่อปักหมุดได้ทันที
- **ใช้แนวทางที่ 3 เป็น "เครื่องมือสนับสนุนกรณีวิกฤต (Crisis Rescue Tool)":** ใช้เมื่อผู้ประสบภัยไม่รู้ตำแหน่ง ติดอยู่ในจุดเสี่ยงตอนกลางคืน หรือเกิดความสับสนในการบอกเส้นทาง
